# 04　数据库与接口设计（草案，不执行迁移）

### 存储边界和关系

浏览器继续持有聊天原文、情绪和个人记忆；SQLite 四张原表见 01。所有新表以空间为边界。时间统一 UTC 毫秒，用户时区只用于解析与展示；ID 由服务端分配。以下为拟增逻辑表，最终 DDL 需在副本上验证。对关联的父表补 UNIQUE(space,id)，子表使用复合外键防止同 ID 跨空间串联；打开 foreign_keys。

|表|关键字段、约束和索引|
|---|---|
|schema_migrations|version PK、checksum、applied_at；校验已执行版本，拒绝未知更高版本。|
|run_steps|space、run_id、seq、kind、status、attempt、call_id、policy_version、input_hash、result_ref、error_code、updated_at；PK(space,run_id,seq)，唯一调用键按 run 约束。关联 runs。|
|command_receipts|space、key、payload_hash、action_id、outcome、entity_ref、created_at；PK(space,key)。同键同参重放，异参 409；写结果与回执同事务，规范化包括工具、来源、参数与版本。|
|memory_grants|space、memory_id、character_id、conversation_id、message_id、action_id、version、state、content_digest、updated_at；PK(space,memory_id)，索引来源；不复制原文。按空间计算带密钥的内容摘要，避免短文本明文哈希猜测。|
|trace_events|space、trace_id、seq、run_id、step_seq、kind、duration_ms、model、input_tokens、output_tokens、error_code、at；PK(space,trace_id,seq)，索引(space,run_id,at)。usage 未提供记 NULL。默认建议保留 7 天，删除来源同步清除。|
|documents / doc_versions|documents(space,id,name,active_version,status,created_at)；doc_versions(space,doc_id,version,hash,mime,parse_status,embed_model,dims,created_at)，联合主键；原文件若保留，用服务端生成的空间内受管路径。|
|chunks|整数 rowid、space、doc_id、version、ordinal、page、heading、start_offset、end_offset、text；唯一(space,doc_id,version,ordinal)。复合外键关联版本，索引授权范围和版本。|
|chunk_fts / chunk_vectors|FTS5 存分词文本并与 chunk rowid 对应，更新/删除在事务内显式维护；向量按 rowid、space、model_version、dims 存储。同模型同维度才可比较；扩展表需单测清理，不能只依赖外键。|
|index_jobs|space、id、doc_id、version、phase、cursor、attempt、error_code；唯一(space,doc_id,version)。可重放写块并以活动版本指针发布；失败只清理草稿。|

### 状态与事务

run 现有 completed 表示该轮回答完成，待确认动作可继续存在。2.0 用独立步骤表示 planned → running → succeeded / failed / interrupted；写工具提案的成功等于卡片已生成。action 保留 pending → executed / rejected / expired，错误确认不得提前标完成。重启只重读安全检查点；缺少临时输入时要求重新提交当前消息，避免为恢复长期留存聊天全文。两个标签页竞争用条件更新或 BEGIN IMMEDIATE，并检查影响行数。

记忆确认拟采用 pending_grant → 浏览器按 actionId 幂等写本地记录 → 服务端核验来源、摘要和策略版本并 ACK → active。客户端查询回执后才展示可检索状态。中断则重发原 ACK；已撤回或过期时取消授权并对账本地孤儿。旧有逐条同意记录通过受控迁入建立授权索引，无法核对来源的记录保留在原存档中供用户确认。

文档索引以新版本写入；成功后在一笔事务切 active_version。删除先封闭所有查询和引用，再清原文件、块、FTS、向量、缓存和 job；文件系统清理失败登记待清理并重试。引用只保存空间内 doc/version/chunk 及定位信息，打开时重新校验。无法撤回已经交给远端供应商或已显示在历史消息中的文字。

### HTTP 合同

前缀 /xinyu-api/agent。空间从服务端 cookie 得出，拒绝客户端指定空间。保留现有 NDJSON 和 snapshot 字段；新字段可选，老前端继续可读。

|方法与相对路径|状态|语义|
|---|---|---|
|POST /runs、GET /state、POST /privacy|现有，拟扩展|发送 turnId/source/messages/context；status/tool/answer/done 等 NDJSON 事件新增 traceId、seq。策略更改使在途运行失效。|
|POST /actions/:id/confirm 或 /reject、POST /manual|现有，拟扩展|确认绑定卡片摘要和政策版本；兼容期旧客户端由服务端推导已存版本。有歧义时返回冲突。|
|DELETE /memories/:id、POST /forget-conversation、DELETE /data|现有，拟扩展|扩展来源清理范围，返回清理结果；不可读立即生效。|
|GET /runs/:id、POST /runs/:id/resume、GET /traces/:id|新增|按空间读取；resume 带 commandId 及预期 stepSeq，冲突返回 409；trace 仅返回脱敏元数据。|
|POST /documents、PUT /documents/:id/content|新增|multipart 文件与本地使用许可，202 返回 docId/jobId；同键重传返回同任务。|
|GET /documents、GET /jobs/:id、DELETE /documents/:id|新增|游标分页、处理进度、删除；删除重复请求幂等；不泄露外空间存在性。|
|POST /knowledge/search、GET /documents/:id/versions/:v/chunks/:chunk|新增|受权查询返回 hits[{docId,version,chunkId,page,heading,excerpt,rank}]；打开引用重查活动版本、归属和删除状态。|

示例：POST /runs/:id/resume 请求 {"commandId":"resume-7","stepSeq":2}；若版本冲突，409 返回 {"error":{"code":"STEP_CONFLICT","message":"进度已变化，请刷新。"},"traceId":"…"}。400 参数、403 授权、404 资源不可见、409 状态冲突、413 太大、415 不支持、429 限流、503 供应商暂不可用。开始 NDJSON 后使用同类错误事件而非改变 HTTP 状态。日志不携带 cookie、密钥、用户正文。

### 备份、迁移、回滚手册（实施阶段）

1. 用户确认维护窗口，记录应用版本、空间数、各表行数和 schema 版本；冻结写入并关停调度。使用 SQLite 一致备份 API，或完全关闭所有连接、成功 checkpoint 后离线复制一致库。不得单独复制正在使用的主文件。浏览器存档需单独通过原存储层制作并验证私有备份；SQLite 备份不覆盖它。
2. 在隔离目录记录备份哈希，验证 integrity_check、foreign_key_check、表计数及代表性假名样本；使用相同 Node 版本演练恢复。备份、密钥、原文件和报告中的私人内容禁止入 Git。
3. 首期只增表/索引；同事务登记 migration 版本和校验和，回填按空间、稳定主键分批，保存游标。文档索引可重建。先双读对比，再切换特性开关；不删除旧字段。注入磁盘满/中断后须能重试。
4. 切换前失败直接事务回滚。切换后先停写并备份故障现场；若已有新写入，先导出并核对增量、确认回放或人工处理策略后再恢复上一个一致快照及匹配程序版本。浏览器和服务器恢复至同一检查点，再核对计数、授权、聊天、提醒及重复确认。未验证增量不得覆盖现库。
