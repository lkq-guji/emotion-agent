# 07　招聘技能对应分析

目标岗位为 AI Agent 应用开发实习。对应关系以可展示的工程产物为准，不推定个人熟练度，也不把上游仓库已有功能算作个人开发成果。

|岗位技能|当前可展示的证据|下一份有说服力的交付|
|---|---|---|
|LLM 接入与工具调用|gateway.mjs、agent.mjs：请求模型、接收 function tool_calls、回传结果、有界循环。|T1/T3：展示相同 Schema 对模型与服务端均生效，非法调用有可读错误。|
|人机协作、事务设计|agent-store.mjs 与 AgentActions.svelte：目标、提醒、专注由确认卡驱动，SQLite 事务执行。|T2/T3/T4：并发确认及进程重启，只生成一条任务，有可查回执。|
|Agent memory 与隐私|memoryRetrieval.mjs、agent.svelte.ts：中文匹配、同意过滤、授权更改及删除来源。|T1/T6：捕获两次请求，展示撤权前后允许字段与来源；用合成数据展示跨端对账。|
|RAG 与语义检索|当前仅能证明个人记忆筛选；没有个人文档知识库完整链路。|T5/T7：导入中文 PDF，点击引用定位页，展示删除后失效及 FTS/向量/混合对照表。|
|可观测性、恢复与成本|目前有 runId、总 token、状态事件和错误摘要。|T4：用一次失败案例展示步骤耗时、重试次数、供应商未知结果及恢复后业务状态。|
|测试、部署与交接|单位测试、服务测试、浏览器测试、跨系统 CI 与单进程本机网关均有源码。|T8：展示干净安装、旧存档升级回滚、匿名评测报告；确定性编排通过率和真模型质量分栏。|
|全栈开发与开源协作|Svelte 5/TS 前端、本机 Node ES 模块与 SQLite；THIRD_PARTY.md 明确上游和自定义边界。|在 PR 中分别标出复用入口、个人实现、验证结果；保留上游许可与素材署名。|

**现在可用的项目描述**：基于 RisuAI 的聊天与存储基础开发本机陪伴 Agent。接入 DeepSeek 工具调用，将对话中的目标、提醒和专注安排转换为待确认卡片，经用户确认后由 SQLite 记录；通过授权开关和来源关联管理个人记忆。

**建议演示顺序**：一次普通倾诉 → 一次带明确时间的任务安排 → 查看待确认状态 → 确认后检查提醒 → 拒绝另一张卡或撤回记忆。升级完成后再加入恢复和引用演示。演示材料使用合成用户，密钥由演示者自行配置。

**证据缺口**：在 T4–T8 交付前，简历不能写“已实现断点工作流、混合 RAG、端到端 Trace、量化提升或生产多租户”。将来写指标应附测试集大小、版本、基线、执行环境和复现方式。个人贡献按实际参与的设计、编码、验证分别描述。
