# 05　分阶段开发任务（尚未开始）

优先次序由风险与依赖决定。第一批交付 T1 和 T8 的隐私用例；第二批 T2/T3；第三批 T4/T6；第四批 T5 与引用链；最后对 T7 做实验并由 T8 放行。每批用独立 PR，在合成或备份副本验收。

## T1　P0　封住出站上下文边界

|项目|内容|
|---|---|
|开发目标|让每次模型请求可解释并受当前授权约束|
|当前代码依据|agent.mjs:50 待确认 args 按空间拼入提示；get_progress 返回对象列表|
|新增或修改模块|runAgent 上下文构建、只读工具 DTO、agent.node.mjs|
|依赖关系|无，第一项开发|
|实现步骤|先拦截假模型请求建立红测；去掉未确认记忆正文和无关会话卡片；按用途投影字段；发送前核验策略版本|
|测试方法|两个对话放不同标记，捕获每次 requestModel，包括工具回传与撤权并发|
|验收标准|禁止标记出站次数为零；同一对话合法进度与原确认仍可用|
|潜在风险|过度过滤会使已有目标无法改期；保留必要真实 ID|
|第三方依赖|无|
|岗位对应|权限边界、LLM 上下文工程、回归测试|

## T3　P0　工具合同与幂等确认

|项目|内容|
|---|---|
|开发目标|工具声明、校验、执行权限可核对；消除重复副作用|
|当前代码依据|agentTools 与 validateAction 分离；propose/manual 使用摘要键，confirm 有事务|
|新增或修改模块|工具注册表、Schema 适配器、command_receipts、确认及手动路由|
|依赖关系|T1、T2|
|实现步骤|迁入七工具并保持名称；收紧分支校验；规范化请求；双端 actionId 回执；同键异参返回冲突|
|测试方法|覆盖七工具合法/非法输入、并发确认、ACK 丢失与撤权|
|验收标准|同键同参得到同回执；异参 409；无确认零业务写入；原手动流程通过|
|潜在风险|旧前端参数兼容、过期或删源后重放|
|第三方依赖|优先复用现有经核实的 JSON Schema 验证器；无适配时评估 Ajv 一个直接依赖|
|岗位对应|Function Calling、Schema、事务与人机协作|

## T4　P1　步骤恢复与可观测

|项目|内容|
|---|---|
|开发目标|能区分模型超时、工具失败、等待确认并定位耗时|
|当前代码依据|runs 记录总量；runAgent 重新进循环；active 为内存映射|
|新增或修改模块|run_steps、trace_events、协调器、provider adapter、Svelte 调试视图|
|依赖关系|T2、T3|
|实现步骤|持久化步骤；加 trace 和耗时；分类退避；新增 resume；在已完成副作用前后设置故障点|
|测试方法|强制断连/终止后重开；模拟 429、超时、缺 usage；快照检查日志|
|验收标准|无重复写；未知结果可解释；trace 跨确认衔接且无原文/凭据|
|潜在风险|重发模型可能重复计费；暂停输入的存储涉及隐私|
|第三方依赖|无，内置时钟与 UUID|
|岗位对应|工作流编排、可靠性、LLM 可观测性|
