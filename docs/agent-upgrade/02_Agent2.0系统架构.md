# 02　Agent 2.0 系统架构（设计）

首版面向单机、单 Node 服务、多个浏览器空间。沿用 Svelte 房间作为聊天入口，保留普通聊天路径；在现有 /xinyu-api/agent 路由内部渐进替换。现有存档继续通过原读写层访问。以下新模块均待实现。

```text
Chat / 确认卡 / 本地知识库 / 调试视图
             ↓ 同源请求、空间 Cookie
Express 网关 → 授权与上下文构建 → run 协调器 ↔ DeepSeek adapter
                                    ↓ tool_calls
                            注册表 + Schema + 业务校验
                          ↙ 只读工具       ↘ 写工具
                    记忆 / 文档 / 进度      提案 → 人工确认
                              ↓                ↓
                       作用域内检索         事务执行 + 回执
                              ↘              ↙
                         SQLite / trace / checkpoint
```

### A　工作流

注册项包含 name、schemaVersion、inputSchema、权限、read/propose 分类和 handler；同一 Schema 同时生成发给模型的 tools 和运行期校验器，保留已有真实 ID、时区、状态迁移等业务验证。解析失败向模型返回可修正错误，有界计次。用户文本、检索片段与工具输出均作为数据，不能提升工具权限。确认绑定空间、来源、有效期、完整参数摘要与策略版本；确认后更改参数须重新核验并展示。

模型轮次与工具步骤分别持久化。只在安全边界续跑。写入、步骤结果和业务回执同一事务提交；确认请求重发时返回原回执。读操作在授权仍有效时可重试。429 尊重 Retry-After，网络瞬断/5xx 带抖动退避最多两次，并受总截止期限约束；校验失败、拒绝、撤权无自动重试。远端请求结果未知时显式记为未知，恢复前展示可能再次产生模型费用。重启重查策略，过期卡不能续签。跨浏览器写记忆采用带稳定 actionId 的本地回执和对账，详见 04。

### B　知识库

授权导入 → 校验大小/扩展名/内容类型 → 本地解析 PDF 文本页或 TXT/MD → 稳定分块 → FTS5 与可选 embedding → 原子发布索引版本。首版扫描 PDF 提示暂无可读文字。保留页号、标题路径、块偏移、文档版本。使用相同中文分词配置建立和查询 FTS；参数绑定并构造安全词项。向量使用同模型、版本、维度与归一化。两路均先隔离空间及可用文档版本，再各取候选并按 RRF（初始 k=60）合并。无相关片段返回证据不足；引用 ID 由服务端核对，点击可回到已授权原文。索引 worker 在同进程排队，重活限并发并与聊天请求分开调度。

### C　记忆

三类来源单独预算。短期上下文取当前对话最近消息；长期记忆走用户逐条授权及来源引用；外部材料通过知识库开关与文档权限检索。文档内容不能自动写入画像或长期记忆。服务端每次构建发送载荷与确认前重新核对授权；浏览器自报 consented 不能代替已登记回执。撤回先阻止读取、取消在途工作，再清理可重建衍生数据；旧聊天中的用户原话由聊天删除操作管理。

### D/E　观测与评测

由服务器生成 traceId，记录模型调用、工具校验、提案、确认、检索、恢复各阶段；跨请求确认关联原 run。默认只存状态、耗时、计数和内部 ID，缺失 usage 标记未知。调试视图按本空间检索，可展开查看错误类别。用受控模型评工作流正确性，用冻结语料评检索，用另行授权的小批真实模型评选择质量；三者分开报告。详细指标见 06。

### F　技术决策

|选项|决定、代价与重新评估条件|
|---|---|
|Svelte 5、TypeScript、Node、SQLite|保留；新增模块使用 TS 类型合同，分段接入现有 .mjs，沿用现有构建和测试。单机部署及数据双存储决定了备份与恢复的边界。|
|轻量自建协调器|优先沿用 runAgent、store.confirm、已有 NDJSON 和原子写入，新增注册表与检查点；尽量只保留一个动作状态真源。|
|LangChain.js|文档解析或检索适配可独立试验；当前七工具和单供应商已有直接协议，全面改用会新增消息转换、流式适配、依赖和回归面。|
|LangGraph.js|具备持久执行、人工中断能力，但需映射 thread/checkpointer 与既有 run/action、处理副作用重播、存档兼容和删除。初版不引入；当出现并行分支、跨日多次中断等真实需求时，用相同故障样例比较实现量、恢复正确率、运行延迟后再决策。[官方持久执行说明](https://docs.langchain.com/oss/javascript/langgraph/durable-execution)|
|SQLite FTS5 + sqlite-vec 候选|本机 Node 内存库已验证 FTS5。用分空间精确向量扫描作参照；sqlite-vec 仅在 Windows/Linux 实际 Node 版本、打包、维度、空间过滤、删除和延迟通过后启用。仅启动时加载锁定的可信扩展，随后禁用加载。失败保留关键词检索，界面显示可用检索方式。[SQLite FTS5](https://www.sqlite.org/fts5.html) · [sqlite-vec JS](https://alexgarcia.xyz/sqlite-vec/js.html) · [Node SQLite](https://nodejs.org/api/sqlite.html)|
|Embedding|单独定义 embed(texts) 接口，记录模型和版本。先用可重复测试向量验证管道，候选本地模型用中文集实测；远程向量化需额外明确授权，不假设现有 DeepSeek 对话接口提供 embedding。|

### 首版运行与交付

沿用 CI 锁定的 Node 24.14.0、pnpm 10.34.1 和 pnpm-lock.yaml；在 web 下执行 pnpm install --frozen-lockfile、pnpm build，再以 node server/xinyu/start.mjs 启动。start.mjs 默认读取 .env.local，也支持 XINYU_ENV_FILE；生产入口默认监听 127.0.0.1:5178。gateway.mjs 从服务端环境读取 XINYU_API_KEY 或 DEEPSEEK_API_KEY，支持 XINYU_MODEL、XINYU_BASE_URL 和 XINYU_AGENT_DB。交接只给占位配置，各人填写自己的 key；不将 key 放入 VITE_*、浏览器请求参数、前端构建或调试事件。使用自定义 base URL 意味着向该服务发送模型数据与凭据，配置仅由本机操作者管理。

默认库位于工作目录下的 .runtime/xinyu-agent.sqlite3；升级前记录实际路径，部署时将数据目录放在构建产物之外。启动检查应分别报告静态页面、数据库、模型配置和索引能力。公开部署需要独立的身份与隔离设计。

首轮分块实验从每块约 400 个中文字符、相邻重叠 60 字开始，按段落/标题切开，PDF 不跨页；超长段落再按句切。数值属于可调基线。用 06 的引用定位和 Recall@5 决定是否改用 token 分块。上传时记录“允许本地索引”和“允许向模型发送检索片段”两项选择；仅选本地时可在本地搜索和看原文。
