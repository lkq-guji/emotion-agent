# Agent 2.0 开发交接

## 第一次启动

工作目录为 web。使用 Node 24.14.0 和 pnpm 10.34.1。运行 `pnpm install --frozen-lockfile`，将 .env.example 复制为 .env.local，用自己的 DEEPSEEK_API_KEY，运行 `pnpm dev`。生产启动用 `pnpm build`、`pnpm start`，默认 127.0.0.1:5178。缺少 key 仍可管理任务、导入资料、本地检索并运行确定性测试。不要将 .env.local、数据库、模型权重或备份加入仓库。新成员使用独立数据库与浏览器空间。

在**记忆 → 本地资料库**导入 UTF-8 TXT、Markdown 或有文本层的 PDF。默认只在本机检索；逐份点击“允许分享”后可在聊天中提问并查看引用。文件替换失败保留上一版。重新导入相同文件不会生成重复版本。更新或删除会使旧引用失效。程序保存分块文本、页号、标题及版本，引用打开定位到抽取段落，未内置完整 PDF 阅读器。

## 模型、索引与评测

- 常规知识检索使用 SQLite FTS5 和中文分词。需要本地语义检索时，在服务端设置 XINYU_EMBEDDING_DIR 为本地 BGE 中文 q8 模型目录并重启；重新导入需补建向量的资料。程序只读本地模型文件，按文件内容指纹和维度隔离向量。导入失败会保留已有版本。关键词模式和语义模式均在候选排序前限制空间与授权。
- 已验证的模型为 Xenova/bge-small-zh-v1.5，修订 75c43b069aac4d136ba6bc1122f995fedcfd2781；使用 config.json、tokenizer.json、tokenizer_config.json、special_tokens_map.json、onnx/model_quantized.onnx。开发时模型和依赖许可证应分别核对。权重由操作者单独准备。[模型文件与修订](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781)
- 产品可选混合检索使用 SQLite BLOB、精确余弦相似度扫描、最低相似度 0.5 和 RRF。sqlite-vec 0.1.9 是**评测依赖**；产品无需在用户数据库启用扩展。先查看匿名评测报告，再决定是否切换默认策略。
- `pnpm eval:agent` 在独立内存库回放 120 条受控场景。`pnpm eval:knowledge` 在无模型时输出关键词指标、原生扩展版本和延迟。设置 XINYU_EVAL_MODEL_DIR 后同一命令比较向量、混合排序和产品路径。
- 若要评估供应商，单独配置 XINYU_EVAL_API_KEY，执行 `node scripts/evaluate-agent.mjs --live`。默认至多 5 例、20 次供应商请求，每次最多 500 个输出 token；可设置 XINYU_EVAL_CASE_LIMIT、XINYU_EVAL_REQUEST_LIMIT 和 XINYU_EVAL_MODEL。脚本只发送工程合成文本。没有真实模型结果时不要引用契约通过率作为模型准确率。

## 升级已有用户库

1. 先停止服务并关闭浏览器。记录实际 XINYU_AGENT_DB、浏览器存储位置、原页面端口和版本。SQLite 存任务，浏览器存原有聊天与空间 cookie；只备份其中一边不足以恢复同一用户空间。
2. 有专用浏览器用户数据目录时，运行 `node server/xinyu/paired-backup.mjs backup <原库文件> <关闭的专用浏览器用户数据目录> <全新备份路径>`。该目录须包含保存聊天的源存储与 cookie。整个浏览器目录可能包含敏感信息，备份应置于自己的私有磁盘。共用浏览器的用户应先用浏览器自身的离线备份流程保护完整配置。勿将个人浏览器资料交给组员。
3. 运行 `node server/xinyu/paired-backup.mjs restore <备份目录> <全新验证目录>`。恢复会逐文件检查 SHA-256，排除不完整副本；在独立目录验证原库和浏览器配对，保留原目录。浏览器 cookie 可能绑定操作系统账户或设备，因此实际恢复须在原账户演练。
4. 在恢复副本上先执行 `node server/xinyu/migration.mjs migrate <副本中的库文件>`。迁移为旧库创建同目录的一致 SQLite 备份，检查完整性和外键，并以事务建立新 schema。重复执行同版迁移可安全返回。用原端口、独立浏览器副本与新服务验证一段旧聊天、一个提醒和一次重复确认。通过后才能安排真实维护窗口并对原库执行同一迁移。
5. 回滚时停止写入，先另存当前双端快照和升级后新增记录，再把上一个版本和上一个双端快照恢复到独立目录。核对增量后切回。工具通过“全新目标路径”约束避免覆盖现有资料。启动发现未迁移的已有库会提示迁移命令。

## API 与恢复边界

现有接口前缀为 /xinyu-api/agent，继续使用同源会话、空间 Cookie、NDJSON。新增 POST /memory-grants、GET /runs/:id、POST /runs/:id/resume、GET /traces/:id。POST /documents 与 PUT /documents/:id/content 接收 application/octet-stream，name 和显式布尔 share 通过查询参数传入。PATCH /documents/:id 可单独撤销分享，DELETE 删除。POST /knowledge/search 接收 query，GET /chunks/:id 打开当前版本片段。资料导入在请求中完成，服务端限制同时一个导入，超额返回 429。

回执在业务写入的 SQLite 事务内完成；同一确认重放不会重复创建任务，异参返回 409。已落盘的提案是安全恢复点；中断恢复后回到原卡片，继续由用户决定。中断发生在模型请求内且没有提案时，点击继续可能产生新的模型用量。调试视图可查看本轮工具与模型事件、耗时和已知 token 数，默认保留七天。调试记录不存正文；正常聊天和 run 的回答仍按原有存档策略保存。

## 交接验证

`pnpm check`、`pnpm test`、`pnpm test:agent`、`pnpm test:gateway`、`pnpm build`、`pnpm test:startup`、`pnpm test:smoke`。Linux 首次运行 Playwright 前按 CI 安装 Chromium。浏览器工程夹具端口为 5190 与 5192，需独占；运行期间编辑网关文件会触发 Vite 重启，造成用例中断。服务测试、迁移与备份测试都使用临时数据。发布前须查看目标平台 CI 的真实结果。
