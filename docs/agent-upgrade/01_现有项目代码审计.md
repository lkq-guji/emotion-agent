## SQLite 与调度

web/server/xinyu/agent-store.mjs 第 53–60 行创建四表与索引。spaces 保存授权开关、策略版本和旧目标导入标记；runs 关联空间、角色、对话及 turn_id，保存状态、回答、总 token 与时间；actions 保存 run_id、工具、JSON 参数、处理结果、状态和失效时间；items 保存目标、专注与提醒，含 JSON details、due_at、goal_id 自引用和 source_run。外键级联会影响来源删除。文件库启用 WAL、外键及 5 秒 busy_timeout。现有索引覆盖到期、空间/类别/状态、动作状态和对话来源。importGoals 带事务及一次性标记。表结构初始化使用 CREATE IF NOT EXISTS，未见版本化升级链。

## 优先风险与复核入口

1. **P0 数据范围**。agent.mjs:50 从空间快照取最多 12 张待确认卡，将 args 拼入 system。A 对话未确认的记忆草案可能进入 B 对话的模型输入。agent.mjs 的 get_progress 还会传最多 50 条任务对象。用捕获出站负载的假模型验证实际字段。
2. **P1 重试边界**。propose 可早于整轮成功。模型中断时卡片仍可确认；同意图重跑若产生不同提醒时间可生成新卡。manual 的 commandId 已存在时直接复用，需识别异参碰撞。
3. **P1 跨存储确认**。客户端写记忆成功、服务端确认响应丢失或权限改变会留下不一致窗口。删除来源需覆盖浏览器存储、SQLite、未来索引和追踪记录，逐类验证。
4. **P2 规模与诊断**。snapshot 最多 200 项任务、80 个动作；不是完整历史分页。服务启动统一标记中断依赖单进程。现有错误摘要不足以重建每一步，不能据此报告模型延迟分位数。
